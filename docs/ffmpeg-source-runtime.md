# AVID Core runtime acquisition

AVID Core owns the FFmpeg/FFprobe source, recipe, native builds and runtime contract. ATIV never builds or selects a separate distribution. Normal production and development builds use the independently authenticated target release in `runtime/platform-runtimes.json`. Every target has its own explicit release identity, archive and source hashes, and executable checksum pins.

The platform acquirer verifies the immutable release identity, the GitHub attestation for `platform-release.json`, its publisher workflow and source commit, then every published asset and the runtime's internal checksums before extraction or execution. The shared `script/core_runtime.py` validates native build metadata and architecture. The Rust library remains pinned to `25d19098a22936638b0e2a70616083d929fe409c`; the packaged runtime is checked against its own authenticated build revision. There is no system/PATH fallback or first-launch media-tool download.

The original authenticated six-target release `ffmpeg-9.0.1-r7.1` remains a compatibility fallback. Select it explicitly with `ATIV_CORE_RUNTIME_SOURCE=legacy`. The build logs identify this choice, and its release manifest attestation and hashes are still verified. Acquisition failure of the selected platform release stops that build; it never silently switches to the legacy release. Packaged metadata records the original archive digest, allowing the embedded validator to distinguish the two pinned, compatible runtime identities. The fallback is temporary and should only be selected for a platform whose application build and runtime specification remain compatible.

For unpublished host qualification only, set `AVID_CORE_QUALIFICATION=1` locally or dispatch `native-release.yml` with `qualify_core_candidate=true`. Candidate origin is pinned to Core commit `25d19098a22936638b0e2a70616083d929fe409c`, maintainer dispatch run `36681249099`, six actual native jobs and GitHub artifact digests. PR/push publication cannot acquire candidates.

Final packages preserve Core metadata and corresponding source. `signed-payload.json` records original and signed derivative hashes without rewriting Core's original checksum manifest. Packaging validates the compiled Core identity and both bundled tools with an empty PATH. See [release integration](release-integration.md) for signing configuration and remaining gates.

## Independent platform releases

`runtime/platform-runtimes.json` pins six immutable AVID Core platform releases from build run `38185320964`. Every entry identifies one target's version, recipe, tag, release and source revisions, successful native job, Actions artifact, and the SHA-256 and GitHub asset ID of each published file. Targets can move independently in later updates. `script/platform_runtime.py` checks the selected release's immutable GitHub identity and requires a GitHub attestation for its `platform-release.json`, bound to the provider publisher workflow, its exact source revision and `refs/heads/main`. The attested provenance binds the target job and artifact identity. Normal acquisition does not depend on temporary Actions artifacts remaining available. Only after authentication does it download the runtime and sources, verify every pinned asset and both checksum sidecars, reject unexpected release assets, validate archive contents and executable architecture, and install the selected target. Reuse of a local cache repeats these checks, including attestation verification. An unrelated failed or unfinished target job does not affect the release. A failure removes the temporary acquisition directory and never falls back to PATH or an unsigned download.

Run `python3 script/ffmpeg_runtime.py provision macos-arm64` for normal acquisition, or `ATIV_CORE_RUNTIME_SOURCE=legacy python3 script/ffmpeg_runtime.py provision macos-arm64` for the explicit compatibility fallback. `python3 -B script/test_platform_runtime.py` exercises the local origin, pin, corruption and failure checks. Signed automatic updates retain their separate verification.
