# Licensing and provenance review

This review records the licensing boundary for ATIV's GPL-3.0-or-later original source. **Do not describe every file in a release ZIP as GPL-3.0-or-later.** The combined Rust engine includes GPL-3.0-only AVID Core, and Windows release packages contain separately licensed Microsoft dependencies. The detailed file-by-file Windows analysis is [docs/WINDOWS_LICENSING.md](docs/WINDOWS_LICENSING.md) with its [exact binary inventory](docs/windows-distribution-inventory.json).

## Original work and provenance

ATIV's current source history has one human author, Tom/Thomas Lothian, and three Dependabot commits. The native Rust, Swift, C, C#, scripts, interface definitions, documentation and packaging code were introduced through that history. The previous Python application is retained on `archive/avid-python` and is not part of current packages. The editable icon's SVG layers and derived platform icons were committed by the maintainer in `d88043d`; `assets/icons/README.md` records the image-generated concept sheet and the derivation of production artwork. No outside human code contribution appears in the available Git history. This is provenance evidence, not proof of exclusive rights to every input.

The host crates declare `GPL-3.0-or-later` in `Cargo.toml`; native package metadata and selected original source entry points carry the same SPDX identifier. The GNU GPL v3 text is in `LICENSE`. `assets/icons/README.md` scopes GPL-3.0-or-later to the maintainer-created production artwork and distinguishes the image-generated reference sheet. Thomas Lothian is the copyright holder for original ATIV work; copyright notices for third-party material remain with their owners.

## Material licensing boundary

ATIV links `avid-core` at commit `3fb68807bc7c350359e1634b32af477ea3042c16`. That crate declares **GPL-3.0-only**. Its `docs/provenance.md` says it incorporates code from EnCap under GPL-3.0-only. GPL-3.0-or-later ATIV host source can be combined under GPL version 3, but the combined engine cannot be offered with a later-version option from ATIV alone. Keep the ATIV source declaration and state the GPLv3-only combined-engine boundary in release notices. Relicensing AVID Core and its EnCap-derived code would require establishing the relevant rights; do not silently change either repository's declarations.

The Windows app builds with `Microsoft.WindowsAppSDK` 2.4 and self-contained Windows App SDK runtime files. The [package terms](https://www.nuget.org/packages/Microsoft.WindowsAppSDK.WinUI/2.3.6/License) permit redistribution of binplaced files in §3 but impose conditions on Microsoft's code. That is a question about **linked and redistributed components**, not a bar to licensing ATIV-owned source GPL-3.0-or-later. The published x64 and ARM64 ZIPs were inventoried file by file. .NET and WebView2 SDK files are permissively licensed; Windows OS and VC++ runtime libraries have a stronger GPLv3 System Library basis. WinUI and other separately supplied Windows App SDK libraries have not been established as System Libraries, and a narrow GPLv3 §7 permission may be necessary for the Windows UI combination. The separate SignPath test expressly permits System Libraries but still requires scrutiny of proprietary SDK files actually bundled. A framework-dependent Windows distribution can keep Microsoft's runtime outside the ZIP; details, exact evidence, and URLs are in the Windows audit.

## Redistributed third-party material

`runtime/ffmpeg/dependency.json` pins FFmpeg 9.0.2, x264 and zlib source hashes. FFmpeg's configured executable is GPL-2.0-or-later, x264 is GPL-2.0-or-later, and zlib uses the zlib license. These licenses can coexist with GPL v3 when their original terms, source and notices are preserved. Packages carry FFmpeg source archives and build records. Rust crates are pinned by `Cargo.lock`; `script/collect_licenses.py` gathers their original license texts for packages. Sparkle is downloaded from its pinned release and its license is copied into the macOS bundle. GTK/libadwaita are LGPL libraries; AppImage packaging may redistribute copies. Windows compiler runtimes and Linux packaging runtimes carry their own notices. See `THIRD_PARTY_NOTICES.md` and `docs/DEPENDENCIES.md`.

Offline Cargo metadata resolves 160 packages and reports a license expression for each. One updater dependency, `webpki-roots` 1.0.9, carries Mozilla CA trust-anchor data under `CDLA-Permissive-2.0`; its upstream repository identifies this as data rather than program source. Preserve its data terms and include it in SBOM/notice review. SignPath's requirement that all components use OSI-approved licenses may warrant clarification for this data component.

Original icon layers, derived icons, documentation, sample preset data and generated platform resources were inspected for external attribution. No stock art, font, audio or video is tracked in the current source tree. Test media is generated locally by `script/create_smoke_media.py`. The image-generated concept sheet's provenance is documented, but its legal status should be reviewed if it is ever redistributed independently as project artwork. Build output in ignored `build/`, `dist/`, `packages/` and `target/` is outside source control; each final package still requires a notice and binary inventory check.

## Release decision

Keep `GPL-3.0-or-later` for original ATIV code. The linked GPL-3.0-only AVID Core component limits the combined engine to GPLv3. For Windows, remove unused AI/ML/Search/Widgets package groups first, then test a framework-dependent WinUI release and determine whether the remaining proprietary Windows UI link needs a copyright-holder-granted additional permission. Do not claim that the current ZIP is entirely GPL-3.0-or-later or SignPath eligible; do not change the license of ATIV-owned code merely because Microsoft runtime files are present.
